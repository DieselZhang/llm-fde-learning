1. 源码构建与运行 mem0 SDK（kp02-01）

1.1 学习目标

学完你能：从零安装 mem0，写一个能 add/search 的最小程序并解释每个关键参数。

1.2 讲解 + 源码走读

安装（README [src]）：

pip install mem0ai                          # 核心 SDK
pip install mem0ai[nlp]                     # + spaCy 实体抽取（hybrid search 需要）
python -m spacy download en_core_web_sm     # + 实体抽取模型

依赖契约：pyproject.toml:15 requires-python = ">=3.10,<4.0"。LLM 默认 gpt-5-mini、embedding 默认 text-embedding-3-small（README [src]），没有 LLM 就不能跑——main.py:946-959 抽取失败会抛 LLMError（不再静默返回空，2026 修复的健壮性改进）。

最小可运行程序（README Basic Usage [src] 精简）：

from openai import OpenAI
from mem0 import Memory

memory = Memory()  # 读 ~/.mem0/ 下配置，默认 OpenAI

# 写入：把这段对话蒸馏成事实
memory.add([
    {"role": "user", "content": "我叫张三，喜欢 Rust 和系统编程"},
    {"role": "assistant", "content": "好的，我记住了！"}
], user_id="alice")

# 检索：多信号融合召回
results = memory.search("张三喜欢什么语言", filters={"user_id": "alice"}, top_k=3)
for r in results["results"]:
    print(r["memory"])

要点：Memory() 零参数即可——默认走 OpenAI + ~/.mem0/ 本地 SQLite；user_id 是作用域隔离的最小单元（main.py:143 _strip_identity_keys 会从 metadata 剥离身份键防篡改）。

1.3 小结

  • 安装 pip install mem0ai + [nlp] extra（hybrid search 需要 spaCy）。
  • 默认 LLM gpt-5-mini / embedding text-embedding-3-small；无 LLM 则 add() 抛 LLMError。
  • Memory() 零参数可用；最小数据流 = add(messages, user_id=...) → search(query, filters)。

2. MemoryConfig 配置与 Provider 工厂注册（kp02-02）

2.1 学习目标

学完你能：看懂 MemoryConfig 结构、知道四类 Provider 如何被工厂注册、能替换默认的 LLM/向量库。

2.2 讲解 + 源码走读

配置结构（mem0/configs/base.py:29）：

MemoryConfig(
    llm=...,
    embedder=...,
    vector_store=...,
    reranker=...,
    history_db_path="~/.mem0/history.db",   # SQLite 审计日志路径
    version="v1.0",
    custom_instructions="...",
)

Provider 配置类在 mem0/configs/<category>/<provider>.py（LLM→configs/llms/ollama.py 等），不在各目录的 configs.py。这是 repo 的目录约定，不是巧合。

工厂注册（mem0/utils/factory.py:42）：

class LlmFactory:
    provider_to_class = {
        "openai": (OpenAILLM, OpenAIConfig),
        "ollama": (OllamaLLM, OllamaConfig),
        # ... 18 个 LLM provider
    }

四类工厂——LlmFactory(18) / EmbedderFactory(11) / VectorStoreFactory(25) / RerankerFactory(5)——统一由 provider_to_class 注册（factory.py:42,79-82）。各分类 __init__.py 为空：注册表在 factory.py，不在模块内。

替换 provider 的例子（换成本地 Ollama + 本地向量库）：

from mem0 import Memory
from mem0.configs.base import MemoryConfig
from mem0.configs.llms.ollama import OllamaConfig
from mem0.configs.embeddings.ollama import OllamaConfig as OllamaEmbConfig
from mem0.configs.vector_stores.qdrant import QdrantConfig

config = MemoryConfig(
    llm=OllamaConfig(model="llama3"),
    embedder=OllamaEmbConfig(model="nomic-embed-text"),
    vector_store=QdrantConfig(host="localhost", port=6333),
)
m = Memory.from_config(config)

2.3 小结

  • MemoryConfig 五要素：llm / embedder / vector_store / reranker / history_db_path。
  • Provider 配置类按 configs/<category>/<provider>.py 组织；注册表统一在 factory.py 的 provider_to_class。
  • 换 LLM/向量库 = 换 config 类，零业务代码改动——这是插件架构的核心收益。

3. 核心 API 用法（kp02-03）

3.1 学习目标

学完你能：完整说出 Memory 的 8 个核心方法、各自签名与用途，知道什么时候用哪个。

3.2 讲解 + 源码走读

方法签名要点用途证据
------------
add(messages, *, user_id, agent_id, run_id, metadata)把对话蒸馏成事实入库main.py:755
search(query, *, user_id, agent_id, run_id, limit, filters)多信号融合召回main.py:1369
get(memory_id)按 ID 取单条main.py（update/delete 附近）
get_all(*, user_id, agent_id, run_id, limit)列出某作用域全部main.py
update(memory_id, data)按 ID 手动改（非 LLM 驱动）main.py:1805
delete(memory_id)按 ID 手动删main.py:1859
delete_all(*, user_id, agent_id, run_id)清空作用域main.py
history(memory_id)审计日志（ADD/UPDATE/DELETE）main.py

关键理解：update/delete 是按 ID 的手动操作，不由 LLM 驱动——这呼应 ADD-only 哲学：写路径只单调累积，改动靠显式人工（m06 详述）。search 的可选参数 explain=True 能逐项拆出 semantic/bm25/entity_boost 分数（scoring.py:127），调试召回质量必备。

平台客户端对比：MemoryClient（client/main.py:82）是托管平台的薄 HTTP 包装——本地不执行逻辑，全部发到 api.mem0.ai（add → POST /v3/memories/add/，client/main.py:184）。签名同 Memory，但行为是远程。

3.3 小结

  • 8 个核心方法覆盖完整生命周期：写（add）/ 读（search, get, get_all）/ 改（update）/ 删（delete, delete_all）/ 审计（history）。
  • update/delete 是手动按 ID，非 LLM 决策——ADD-only 的体现。
  • Memory（本地 OSS）与 MemoryClient（远程平台）签名镜像，行为完全不同。
