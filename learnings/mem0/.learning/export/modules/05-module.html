1. search() 检索数据流（kp05-01）

1.1 学习目标

学完你能：按顺序说出 search() 的 8 个步骤、每步输入输出、为什么先 over-fetch 再融合。

1.2 讲解 + 源码走读

8 步骤（main.py:1618-1685）：

#步骤做什么证据
------------
1预处理 query词形还原（供 BM25）+ 实体抽取main.py:1624-1625
2embed queryquery → 向量main.py:1628
3语义检索over-fetch max(limit×4, 60) 候选池main.py:1631-1634
4关键词检索keyword_search（如向量库支持）main.py:1637-1639
5BM25 归一sigmoid 按查询长度自适应main.py:1642-1649
6实体加分_compute_entity_boostsmain.py:1651-1654
7候选集过滤过期记忆main.py:1656-1667
8融合排序score_and_rank → top_kmain.py:1669-1685

关键设计——over-fetch：语义检索先拉 max(limit×4, 60) 个候选（main.py:1631），再做 BM25/实体打分融合，最后裁剪到 top_k。为什么：单靠语义 top-k 会漏掉"语义分略低但 BM25/实体强命中"的记忆；over-fetch 扩大了评分池，融合才有效。代价是召回池膨胀（m06 的 ADD-only 代价之一）。

1.3 小结

  • search() 8 步：预处理 → embed → over-fetch 语义 → 关键词 → BM25 归一 → 实体加分 → 候选 → 融合。
  • over-fetch（limit×4，≥60）扩大评分池，融合后才裁剪到 top_k。
  • 预处理同时做词形还原（BM25）与实体抽取（实体加分）。

1.4 课后思考题

  • kp05-01（concept）：如果把 over-fetch 去掉，直接语义 top_k 后融合，会漏掉哪类记忆？举一个具体场景。

2. 加性融合打分公式与 threshold 门控（kp05-02）

2.1 学习目标

学完你能：默写融合公式、解释 max_possible 自适应、说清 threshold 先作用于哪个分数。

2.2 讲解 + 源码走读

融合公式（scoring.py:60-139）：

raw_combined = semantic_score + bm25_score + entity_boost
combined = min(raw_combined / max_possible, 1.0)

max_possible 自适应（scoring.py:97-101）：

激活信号max_possible
------
仅语义1.0
语义 + BM252.0
语义 + 实体1.5
语义 + BM25 + 实体2.5

为什么自适应：不同信号激活时分数量纲不同——不除以总可能最大值，激活信号多的候选天然分高（不公平）；归一后各信号组合可比。

threshold 门控（scoring.py:111）：

if semantic_score < threshold:
    continue    # 直接丢弃，即使 BM25/实体能抬升

关键理解：threshold 先作用于语义分再融合——语义分低于阈值的候选直接丢弃，不给 BM25/实体"救回来"的机会。这是质量底线：语义完全不相关的记忆，光靠关键词/实体命中不该进上下文。

2.3 小结

  • combined = min((semantic + bm25 + entity_boost)/max_possible, 1.0)。
  • max_possible 按激活信号数自适应（1.0/2.0/1.5/2.5），保证跨组合可比。
  • threshold 先滤语义分——语义不相关就丢弃，BM25/实体不兜底。

2.4 课后思考题

  • kp05-02（concept）：一条记忆语义分 0.09、BM25 归一 0.9、实体加分 0.4，threshold=0.1 时最终结果是什么？如果把 threshold 挪到融合之后，会发生什么变化？

3. 为什么是加性融合而非 RRF（kp05-03）

3.1 学习目标

学完你能：说清 RRF 与加性融合的本质区别、解释 mem0 为什么选加性融合。

3.2 讲解 + 源码走读

两种融合方式：

RRF（Reciprocal Rank Fusion）mem0 加性融合
---------
依据排名：Σ 1/(k + rank_i)分数：(sem + bm25 + entity)/max_possible
输入各检索器的 top-k 排名各信号已归一分数
分数尺度可不比较（排名即可）必须可比较（需归一）
可解释性差（分数无直接含义）好（explain=True 逐项拆出）
可调参弱强（权重、threshold、BM25 参数）

为什么 mem0 选加性融合（design 关键）：

  1. 分数本身有意义：mem0 的 semantic/bm25/entity 都归一到 [0,1]，量纲可比 → 直接相加是合理近似；RRF 丢弃了分数信息，只用排名。
  2. 可解释可调试：explain=True 能逐项拆出每个信号贡献（scoring.py:127）——RRF 做不到，出了问题无法定位。
  3. 设计一致性：融合公式、BM25 sigmoid 参数、实体加分权重都是显式可调的（scoring.py:57 ENTITY_BOOST_WEIGHT=0.5）——整个读路径是"白盒打分"，符合"memory is retrieval"的哲学。

RRF 何时更合适：异构检索器分数尺度不可比时（比如混合了语义 + 布尔检索 + 个性化排序），排名融合更鲁棒。

3.3 小结

  • RRF 用排名融合，加性融合用分数融合——本质是"丢弃 vs 保留分数信息"。
  • mem0 选加性融合：分数可解释、可调参、与白盒哲学一致。
  • RRF 适合分数尺度不可比的异构检索器。

3.4 课后思考题

  • kp05-03（design）：如果某向量库的 semantic 分数和 BM25 分数量纲不可比（比如一个 [0,1] 一个 [0,50]），mem0 的加性融合会怎么失败？要如何改造才仍能用加性融合？

4. 实体加分机制与 explain 可解释性（kp05-04）

4.1 学习目标

学完你能：复述实体加分的公式与直觉、说明 explain 如何帮助调试。

4.2 讲解 + 源码走读

实体加分（main.py:1723-1803 _compute_entity_boosts）：

query 实体 → embed → 实体库搜索(threshold≥0.5)
对每个命中实体:
  boost = similarity × ENTITY_BOOST_WEIGHT(0.5) × memory_count_weight
  memory_count_weight = 1 / (1 + 0.001 × (n_linked - 1)²)
  对每个 linked_memory: boosts[id] = max(boosts.get(id,0), boost)

设计直觉：

  1. ENTITY_BOOST_WEIGHT=0.5（scoring.py:57）：实体只是增强信号，加分封顶 0.5，不能让实体命中压过语义主分。
  2. memory_count_weight 降权：一个实体关联的记忆越多（n_linked 大），单个记忆分到的加分越小（main.py:1792）——避免"常见实体"把一堆记忆全抬上去（稀释效应）。
  3. max 取最大值：同一记忆被多个实体命中，取最大的 boost（main.py:1798），不叠加——防止堆叠失衡。
  4. 并发：多个实体的实体库搜索用 ThreadPoolExecutor(max_workers=4)（main.py:1768）并行。

explain 可解释性（scoring.py:126-135）：explain=True 时每个结果带 score_details：

{"semantic_score": 0.7, "bm25_score": 0.4, "entity_boost": 0.2,
 "raw_score": 1.3, "max_possible_score": 2.5, "final_score": 0.52, "threshold": 0.1}

调试价值：一条记忆为什么排第 3？看 score_details 就知道是语义弱还是 BM25 没命中还是实体没加分——把黑盒打分变成可归因。

4.3 小结

  • 实体加分 = similarity × 0.5 × 记忆数降权，封顶 [0, 0.5]；max 去重不叠加。
  • 降权直觉：关联越多分越少，避免常见实体稀释。
  • explain=True 逐项拆出 semantic/bm25/entity/raw/final/threshold——白盒可归因。

4.4 课后思考题

  • kp05-04（design）：如果去掉 memory_count_weight，一个被 100 条记忆关联的实体命中 query 时会发生什么？为什么这有危害？

章节总结

本章心智模型：search() 是一条"扩大再融合"的管线——over-fetch 扩大候选池，然后语义 + BM25 + 实体三信号加性融合，threshold 先卡语义质量底线。核心哲学是白盒打分：分数可解释（explain）、可调参（权重/阈值/BM25 参数）、可归因（每项贡献可见）。这不是 RRF 的黑盒排名，是显式的分数决策。

关键 file:line 索引：main.py:1618-1685（8 步数据流）、:1631（over-fetch）、:1723-1803（实体加分）、scoring.py:60-139（融合公式）、:97-101（max_possible 自适应）、:111（threshold 门控）、:57（ENTITY_BOOST_WEIGHT）、:126-135（explain）。

与整体架构的钩子：search() 消费 add() 写的 linked_memory_ids 做实体加分；"读路径反复打分裁决"正是 m06 ADD-only 哲学的镜像。
