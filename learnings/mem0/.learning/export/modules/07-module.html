1. 用 OSS 搭建可运行的 add/search demo（kp07-01）

1.1 学习目标

学完你能：从零搭一个可运行的 mem0 demo，解释每条关键配置，并验证 ADD-only 与融合打分的行为。

1.2 讲解 + 源码走读

准备环境（读路径依赖本地 LLM 时用 Ollama）：

pip install mem0ai[nlp]
python -m spacy download en_core_web_sm
# 可选: 本地 LLM + embedding
ollama pull llama3
ollama pull nomic-embed-text

demo 1 — 最简 add/search（验证数据流，走 OpenAI 默认）：

from mem0 import Memory
m = Memory()

# 写入：蒸馏成事实
m.add([
    {"role": "user", "content": "我叫张三，喜欢 Rust 和系统编程，最近在读操作系统源码"},
    {"role": "assistant", "content": "好的，已经记住了！"}
], user_id="demo")

# 检索：explain 看分数构成
r = m.search("张三的编程偏好", user_id="demo", top_k=3, explain=True)
for item in r["results"]:
    print(item["memory"], "→", item.get("score_details", {}).get("final_score"))

预期观察：返回的是抽取后的事实（不是原始对话句），且 score_details 里有 semantic/bm25/entity 各项——这就是 m04/m05 讲的管线在真实运行。

demo 2 — 验证 ADD-only 行为（本地 LLM，数据不出域）：

from mem0 import Memory
from mem0.configs.base import MemoryConfig
from mem0.configs.llms.ollama import OllamaConfig
from mem0.configs.embeddings.ollama import OllamaConfig as EmbCfg
from mem0.configs.vector_stores.chroma import ChromaConfig

config = MemoryConfig(
    llm=OllamaConfig(model="llama3"),
    embedder=EmbCfg(model="nomic-embed-text"),
    vector_store=ChromaConfig(),
)
m = Memory.from_config(config)

动手验证清单（每项对应课程知识点）：

  1. add 两次同一句话 → MD5 去重生效（m04-03），第二次不产生重复记忆。
  2. search 一段完全无关的话 → threshold 过滤（m05-02），返回空或极少。
  3. explain=True → 看到三项分数构成（m05-04）。
  4. 改一句"改主意"的话 → 新旧事实并存（m06-02），验证 ADD-only 无冲突消解。

1.3 小结

  • 最简 demo = Memory() + add + search(explain=True)，走默认 OpenAI。
  • 本地 demo = 换 Ollama LLM/embedding + Chroma 向量库，数据不出域。
  • 动手验证清单对应 m04/m05/m06 核心结论，是"看得见的证据"。

2. 自研 vs 集成 mem0 的决策链（kp07-02）

2.1 学习目标

学完你能：面对任意"要不要用 mem0"的场景，走出一条有依据的决策链，而非拍脑袋。

2.2 讲解 + 源码走读

核心分界：要不要在写路径做 LLM 蒸馏？

要不要写路径LLM蒸馏？
├── 不要（只要文本相似）→ 裸向量库 + 自写 RAG
│     理由: mem0 的写路径成本（LLM token、抽取延迟）对你的需求是纯开销
├── 要，标准事实场景 → 集成 mem0
│     理由: 写路径抽取 + 多信号召回 + 隔离 + 生命周期，全都现成
├── 要，强领域结构 → fork mem0 OSS 深度定制
│     理由: 替换 prompt（configs/prompts.py）/ 融合权重（scoring.py）/ 存储
│           ——比从零自研划算得多
└── 从零自研只在"连骨架都要重写"时

附加判据（m06 的边界落地）：

问题指向
------
数据能出境吗？否 → OSS + 本地 LLM（Ollama）
召回需求是文本相似还是事实级？事实级 → mem0；文本级 → 向量库
要生命周期/多租户隔离吗？要 → mem0 内置；不要 → 可省
成本敏感？每次 add 烧 LLM token → 控频率 / infer=False
要时间推理/矛盾消解吗？要 → 考虑 Zep（m01-03）

代码证据：configs/prompts.py:468（替换抽取 prompt 的入口）、utils/scoring.py:57,97-101（调融合权重/自适应）、utils/factory.py:42（换存储）。

2.3 小结

  • 决策链第一问：要不要写路径 LLM 蒸馏——答案分叉到裸向量库 / 集成 / fork / 自研。
  • 附加判据：出境、召回粒度、生命周期、成本、时间推理。
  • fork 比自研划算：替换点都在 configs/prompts/scoring/factory，骨架可复用。

2.4 课后思考题

  • kp07-02（design）：你的团队已经有一个裸向量库 RAG 在跑文档问答，现在要加"记住用户偏好"功能。用决策链分析：是扩展现有 RAG、集成 mem0、还是 fork mem0？给出完整推理。

章节总结

本章心智模型：把六章认知收束成一句选型格言——"要不要写路径 LLM 蒸馏"决定架构边界，数据出境决定 OSS/平台，时间推理决定 mem0/Zep。动手实验证明的不只是"能跑"，更是 m04/m05/m06 的设计判断在真实数据上成立。
