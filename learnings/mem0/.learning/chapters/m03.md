## 1. 分层架构与依赖方向（kp03-01）

### 1.1 学习目标

学完你能：画出 mem0 的四层架构图，并说出依赖方向（谁依赖谁、谁不依赖谁）。

### 1.2 讲解 + 源码走读

**四层架构**：

```
┌─────────────────────────────────────────────┐
│  入口层  Memory / AsyncMemory / MemoryClient │
│           (main.py / client/main.py)         │
├─────────────────────────────────────────────┤
│  配置层  MemoryConfig + configs/<cat>/<prov> │
│           (configs/base.py + configs/*/)     │
├─────────────────────────────────────────────┤
│  Provider层  LLM / Embedder / VectorStore /  │
│               Reranker  (factory.py 注册)    │
├─────────────────────────────────────────────┤
│  存储层  向量库(事实+实体) · SQLite(messages │
│           + history)                        │
└─────────────────────────────────────────────┘
```

**依赖方向**：**自上而下**——入口层持有配置层与 Provider 工厂，Provider 层读写存储层。**关键设计点**：

1. **入口层与 Provider 解耦**：`Memory` 不直接 `import` 某个具体 LLM，而是通过 `LlmFactory` 按名字解析（`factory.py:79-82`）——所以换 provider 零业务改动（m02 已验证）。
2. **配置与实现分离**：`MemoryConfig` 只声明"要什么"，实际类的实例化由工厂完成（`factory.py:42`）。
3. **AsyncMemory 是镜像**：`main.py:2156` 的 `AsyncMemory` 与 `main.py:482` 的 `Memory` 是**逐方法镜像的孪生类**，异步版用 `asyncio.to_thread` 包阻塞调用，管线逻辑完全相同——架构不因同步/异步而分叉。

**核心证据**：`Memory.__init__` 里通过 `LlmFactory` / `EmbedderFactory` / `VectorStoreFactory` 解析 config 中的 provider 名（`factory.py`），而不是 `from mem0.llms.openai import OpenAILLM` 直接硬编码。

### 1.3 小结

- 四层：入口 / 配置 / Provider / 存储，依赖自上而下。
- 入口层与 Provider 通过工厂解耦——插件架构的骨架。
- 同步 `Memory` 与异步 `AsyncMemory` 是镜像孪生，不引入两套设计。

### 1.4 课后思考题

- **kp03-01（concept）**：如果让 `Memory` 直接 import 一个具体 LLM 类，架构上会失去哪两个能力？（提示：扩展性 + 测试性）

## 2. 三层存储模型（kp03-02）

### 2.1 学习目标

学完你能：说清三类存储各存什么、谁可检索、为什么这样分工。

### 2.2 讲解 + 源码走读

```
向量库（可检索）     → 抽取后的事实（主集合） + _entities 实体集合
SQLite messages      → 原始消息，每会话滚动 10 条，仅供抽取上下文，不可检索
SQLite history       → ADD/UPDATE/DELETE 审计日志
```

**分工逻辑**（这是理解 mem0 存储设计的钥匙）：

| 存储 | 内容 | 可检索？ | 用途 | 证据 |
|---|---|---|---|---|
| **向量库** | 蒸馏后的事实 + 实体 | ✅ | 语义/BM25/实体召回 | `main.py:982-993`（embed）、`main.py:1077+`（实体） |
| **SQLite messages** | 原始消息滚动 10 条/会话 | ❌ | 仅供 LLM 抽取时的上下文 | `storage.py:257`（滚动 10 条） |
| **SQLite history** | ADD/UPDATE/DELETE 审计 | ❌ | 生命周期审计（`history()` API） | `storage.py:102` |

**"不存原始对话块"的精确说法**：不是"完全不存原始消息"——原始消息以每会话 10 条滚动窗口存 SQLite（`get_last_messages` `main.py:910`），**仅供抽取上下文，不参与检索**。检索面只有向量库里的蒸馏事实。`infer=False` 时直接存原文是例外。

### 2.3 小结

- 三层存储：可检索的向量库（事实+实体）、不可检索的 messages（抽取上下文）、history（审计）。
- "不存原始对话块"精确含义：原始消息存但不参与检索。
- 存储分工 = "什么该被想起"（向量库）vs "什么只是过程"（SQLite）。

### 2.4 课后思考题

- **kp03-02（concept）**：如果让原始消息也可检索（比如全量进向量库），架构上会失去什么、换来什么？

## 3. Memory / AsyncMemory / MemoryClient 的关系与选择（kp03-03）

### 3.1 学习目标

学完你能：说清三个入口类各自定位、何时用哪个、为什么接口镜像。

### 3.2 讲解 + 源码走读

| 类 | 定位 | 核心区别 | 证据 |
|---|---|---|---|
| `Memory` | OSS 自托管（同步） | 本地执行全部管线 | `main.py:482` |
| `AsyncMemory` | OSS 自托管（异步） | 与 Memory 镜像，`to_thread` 包阻塞调用 | `main.py:2156` |
| `MemoryClient` | 托管平台（同步） | 薄 HTTP 包装，无本地逻辑 | `client/main.py:82` |
| `AsyncMemoryClient` | 托管平台（异步） | MemoryClient 的异步镜像 | `client/main.py:1123` |

**三句话理解**：

1. **同步 vs 异步不是两套设计**：`AsyncMemory` 用 `asyncio.to_thread` 把 `Memory` 的阻塞调用丢到线程池，管线逻辑共享（`main.py:2156` 镜像 `main.py:482`）。
2. **OSS vs 平台是两种执行位置**：`Memory` 在本地跑抽取/检索；`MemoryClient` 把参数序列化 POST 到 `api.mem0.ai`（`client/main.py:184`），本地零逻辑。
3. **选择判据**：数据能否出境（合规 → OSS `Memory` + 本地 LLM）；要不要托管运维（省事 → `MemoryClient`）；写高并发异步场景 → `AsyncMemory`。

**接口镜像的工程价值**：四个类方法签名一致 → 切换 OSS/平台/同步/异步只改一行 import，业务代码不动。这是"接口稳定 = 可替换性"的教科书案例。

### 3.3 小结

- 四类入口 = 同步/异步 × OSS/平台 的笛卡尔积，接口镜像。
- `AsyncMemory` 用 `to_thread` 复用 `Memory` 管线，非重写。
- `MemoryClient` 是薄 HTTP 客户端，不执行任何本地逻辑。
- 接口镜像 → 一行切换，可替换性极强。

### 3.4 课后思考题

- **kp03-03（concept）**：一个已有 `MemoryClient` 的线上服务要迁到 OSS 自托管（数据不能出境），代码层最少改什么？哪些行为会变、哪些不变？

## 章节总结

**本章心智模型**：mem0 的骨架 = 四层依赖（入口→配置→Provider→存储，自上而下）+ 三层存储（可检索向量库 / 抽取上下文 SQLite / 审计 history）+ 四入口镜像（同步/异步 × OSS/平台）。掌握这三张图，任何 mem0 问题你都能先定位到"哪一层、哪个存储、哪个入口"再深入。

**关键 file:line 索引**：`main.py:482`（Memory）、`main.py:2156`（AsyncMemory）、`client/main.py:82,1123`（平台客户端）、`factory.py:42`（Provider 注册）、`storage.py:102,257`（SQLite）。

**与整体架构的钩子**：m04 的 `add()` 和 m05 的 `search()` 就是在这个骨架上跑的两条主数据流；m06 的设计哲学解释骨架为什么长这样。

## Cheatsheet（memory 型，参考用）

```text
四层: 入口 → 配置 → Provider(工厂) → 存储     （依赖自上而下）
三层存储:
  向量库   = 蒸馏事实 + _entities 实体集合      （可检索）
  messages = 原始消息滚动10条/会话               （抽取上下文, 不可检索）
  history  = ADD/UPDATE/DELETE 审计日志
四入口:
  Memory / AsyncMemory         OSS 自托管 (同步/异步镜像)
  MemoryClient / AsyncMemoryClient  托管平台 (薄HTTP包装)
接口镜像 → 换 OSS/平台/同步/异步只改一行 import
```
