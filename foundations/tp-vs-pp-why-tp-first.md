# TP vs PP：为什么通信量大的反而优先推荐？

> 核心问题：TP 每层都需要 AllReduce（通信量大），PP 只在层边界传递激活值（通信量小），但部署策略却推荐优先 TP。这是为什么？

---

## 1. 通信量 ≠ 通信时间

### TP 的 AllReduce 跑在 NVLink 上（极快）

```
单机 8 × H100 NVLink 4.0:
  双向带宽: 900 GB/s per GPU

  Llama-3-70B, TP=8, 每层 AllReduce 数据量:
    激活值: 4096 × 8192 × 2 bytes ≈ 64 MB
    AllReduce 时间: 64 MB / 900 GB/s ≈ 70 微秒

  80 层: 80 × 70 μs ≈ 5.6 ms
  相比计算时间 (~50-200 ms)，AllReduce 只占 3-10%
```

### PP 的层间传递可能走网络（慢）

```
跨节点场景 (IB NDR400: ~50 GB/s):
  传递一层激活值: 4096 × 8192 × 2 ≈ 64 MB
  传递时间: 64 MB / 50 GB/s ≈ 1.3 毫秒

  PP 只在层边界传递，但跨节点单次延迟
  可能等于 TP 80 次 AllReduce 总延迟的同级别
```

---

## 2. Pipeline Bubble：PP 的真正代价

TP 不存在、PP 极其严重的代价：GPU 空闲等待。

```
PP=4 的执行时间线:

  GPU0 (L0-19):  [████]............[████]
  GPU1 (L20-39): ......[████]............[████]
  GPU2 (L40-59): ............[████]............
  GPU3 (L60-79): ..................[████]

  ████ = 实际计算
  .... = 空闲等待（Pipeline Bubble）

  稳定状态下 GPU 利用率 ≈ 70-80%（无法达到 100%）
```

TP 没有这个问题：

```
TP 的执行时间线:

  GPU0: [████████████████████████]  100% 利用率
  GPU1: [████████████████████████]  100% 利用率

  AllReduce 穿插在每层之间（微秒级），不影响利用率
```

---

## 3. 数字验证

```
场景: 405B 模型，跨 3 节点

方案 A: 纯 TP=24（跨节点，每层 AllReduce 走网络）
  总 forward: ~420 ms  ← 通信主导

方案 B: TP=8 (机内 NVLink) + PP=3 (跨节点)
  总 forward: ~133 ms  ← 约 3 倍快
  机内 AllReduce: ~5.6ms + 跨节点 PP: ~2.6ms + bubble(25%): ~25ms + 计算: ~100ms
```

---

## 4. 正确决策树

```
1. 单卡放得下模型？
   → 是 → DP（最简单，零通信）

2. 单机多卡放得下？
   → 是 → TP（NVLink 加速，无 bubble，GPU 利用率 100%）

3. 必须跨机
   → TP(机内) + PP(跨机)
     机内 AllReduce 走 NVLink（快）
     跨机用 PP 减少跨机通信次数
     代价：Pipeline Bubble
     缓解：micro-batch 填充 bubble

为什么不是纯 PP？
  PP=8 时 bubble 极其严重，GPU 利用率可能 < 50%
  8 张 GPU 的 TP 利用率 100%，即使有 AllReduce 也远胜 PP
```

---

## 5. 核心总结

| 维度 | TP | PP |
|------|----|----|
| 通信方式 | 每层 AllReduce | 层边界传递激活 |
| 通信次数 | 很多（每层） | 很少（层边界） |
| 单次通信速度 | 极快（NVLink 900 GB/s） | 可能慢（跨机 IB 50 GB/s） |
| GPU 利用率 | 100%（无 bubble） | ~70-80%（Pipeline Bubble） |
| 调度复杂度 | 低 | 高（micro-batch 调度） |
| 使用场景 | 单机多卡 | 必须跨机时 |

**"DP > TP > PP" 不是性能排序，是工程复杂度排序。NVLink 让 TP 的通信开销在实际中几乎不是瓶颈，而 PP 的 Pipeline Bubble 是结构性代价，无法完全消除。**
